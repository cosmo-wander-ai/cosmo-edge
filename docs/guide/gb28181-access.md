# GB28181 设备接入

国标接入分成两件事：设备向平台注册，以及平台选择视频通道发起点播。仅填写视频通道编码，不能替代 SIP 服务器、域、设备身份和认证配置。本分支是第一版管理接入试用实现，不代表完整国标认证或所有厂商兼容性验收。

## 架构与复用

CosmoEdge 管理 SIP/TCP 注册、Digest MD5 认证、心跳、Catalog 目录及 INVITE/ACK/BYE。SRS 只负责 PS/TCP 收流和转封装。内部使用 `rtmp://127.0.0.1:1936/live/<视频通道编码>`，继续复用已有解复用、解码、算法任务、预览、抓拍、录像和告警链路。

设备编码与视频通道编码分别处理。同一查询的分批目录完整收齐后才更新；多个设备上报相同视频通道编码会提示冲突，不进行模糊匹配。原有 `gb28181://<20位编码>` 通道无需改地址，但编码必须能在已登记设备目录中找到。

当前边界：

- 面向具备 GB28181 TCP 能力的设备；平台被动收媒体，摄像机主动建立 TCP 连接。这是受限 SIP 子集，不是通用 SIP 代理。
- 最多登记 128 台设备、同时保持 64 个 SIP 连接、每次设备目录最多 1,024 项、最多维护 256 路媒体需求；实际视频/解码数量仍受平台原有限制。
- H.264 优先验证；H.265 仍须按摄像机封装、目标硬件和浏览器分别实测。
- 暂不支持 UDP、平台主动建立媒体 TCP、SIP TLS、SHA-256 Digest、Record-Route/级联代理、目录订阅、PTZ、语音业务及国标录像检索/回放。目录不响应时不会自动猜测视频通道。
- NVR 多通道模型和目录分页有模拟测试，不等于所有 NVR 厂商已实测通过。

## 参数对应关系

在视频通道中点击“新增”，接入类型选择 GB28181，打开“国标设备接入”。页面只保留“平台设置”和“设备与通道”两个页签。

| 摄像机参数 | CosmoEdge 对应位置 | 说明 |
| --- | --- | --- |
| SIP 服务器 ID | 平台设置 → SIP 服务器 ID | 平台身份，所有接入设备填写相同值 |
| SIP 服务器域 | 平台设置 → SIP 服务器域 | 同时作为 Digest realm，两边必须一致 |
| SIP 服务器地址 | 本平台摄像机可访问的地址 | 不是摄像机自己的 IP |
| SIP 服务器端口 | 平台设置 → SIP 服务器端口 | 默认 TCP 5060 |
| SIP 用户名 | 设备与通道 → 设备编码 | 设备的 20 位国标身份 |
| SIP 用户认证 ID | 设备的高级认证设置 | 默认等于设备编码，允许不同 |
| 密码 | 设备与通道 → SIP 认证密码 | 两边必须一致，不自动使用网页登录、ONVIF 或平台管理员密码 |
| 视频通道编码 ID | 摄像机目录自动返回 | 可与设备编码不同，一台 NVR 可有多个通道 |
| 传输协议 | TCP | 摄像机主动连接平台媒体端口 |

新登记设备默认必须设置密码，编辑时留空保留原密码。注册摘要保存在私有、加密、原子更新的配置中，查询接口不返回密码或摘要。域参与摘要计算，因此已有设备登记时不能直接修改域，需重新登记并设置密码。

“此设备不校验密码”是默认关闭的显式兼容选项，仅用于可信隔离网络。它只校验编码，不能证明设备身份，其他设备可能冒用同一编码；未登记编码仍不放行。明文 HTTP 管理与 SIP/TCP 不提供传输加密，请勿直接暴露到公网。

## 最简接入步骤

1. 在“平台设置”确认服务器 ID、域和 SIP 端口，启用后保存。“SIP 服务器地址”默认自动选择摄像机实际连接的本机 IPv4 网卡，也可下拉选择固定网卡 IP；跨 NAT/特殊路由时在高级地址设置中手动指定。摄像机端仍需填写可访问的盒子 IP，自动模式不会直接保存浏览器登录地址。
2. 在“设备与通道”登记设备编码与 SIP 密码。认证 ID 不同时在高级设置中填写。
3. 在摄像机“平台接入”填写对应参数，启用 GB28181、选择 TCP 并保存。
4. 等待注册及自动查询目录，展开设备，修改所需视频通道名称后添加。无需填写播放地址，不会自动导入所有目录项。
5. 回到视频输入列表预览，按原流程分配算法任务。已有相同逻辑地址的通道会标记“已添加”。

保存平台设置会断开现有国标注册，等待摄像机重新注册恢复；修改设备认证也要求其重新注册。删除登记不删除原视频通道和算法任务，但相关通道会离线。

## 运行配置与旧版本迁移

SRS 媒体收流器随包启用，但其内置 SIP 关闭，不再无认证注册后自动邀请。CosmoEdge 管理 SIP 默认关闭，必须在页面显式启用。

旧部署的 `COSMO_GB28181_ENABLED`、`COSMO_GB28181_SIP_PORT`、`COSMO_GB28181_CANDIDATE` 不再决定管理版 SIP 开关、端口或通告地址，以页面持久化配置为准。`COSMO_GB28181_MEDIA_PORT` 仍由启动脚本渲染给 SRS，默认 TCP 9001，须避开 WebSocket 9000。摄像机需能访问 SIP 和媒体端口。

SRS 媒体分配/释放 API 仅接受本机回环 POST，公开 RTC API 行为不变。未分配的媒体不会自动建立业务通道。

配置位于 `${COSMO_DATA_DIR}/conf/gb28181/`，备份/恢复必须同时保留 `key` 和 `settings.json`，并与业务通道配置一起纳入升级回滚。密钥缺失、损坏或解密失败不会降级成免认证模式。

升级时保留原视频通道，登记真实设备身份和密码并查询目录。原逻辑地址中的编码应当对应视频通道，不要假设注册编码与视频编码永远相同。

## 状态与排查

| 状态 | 优先检查 |
| --- | --- |
| 等待注册 / SIP 未监听 | 平台启用开关、端口占用、防火墙、摄像机服务器地址与设备编码 |
| 认证失败 | SIP 认证 ID、域和 SIP 密码，而非网页登录账号 |
| 目录查询失败 | Catalog 支持情况、响应完整性；可手动重新查询 |
| 点播中 / 点播拒绝 | 视频通道编码、返回的 SIP 状态码、设备传输能力 |
| 等待媒体 / 媒体超时 | 通告地址、TCP 媒体端口、摄像机 TCP 主动发送能力 |
| 正在收流 | 只表示有活动发布；解码、画面与任务仍须分别验证 |

注册/心跳过期会下线，重新注册后刷新目录；点播失败按超时和重试间隔恢复。删除业务通道后媒体需求最长约 120 秒失效，活动算法通道也会续期需求，避免运行中误回收。媒体端有独立的未开流/无数据租约，防止失败点播永久占用会话。这些机制不代表瞬间重连。

本版将 SRS 的音视频交错等待队列限制为约 200 毫秒的时间戳跨度或 32 个消息，避免纯视频或音频中断时等待超过 100 个视频包。这不是端到端延迟上限：摄像机、关键帧、网络、解码和播放器仍有缓存。RTSP 与国标延迟应在相同码流、编码、分辨率、帧率、I 帧间隔及预览方式下比较。

RTMP 读取策略同时使用较短的流信息探测（500 毫秒分析时长、1 MiB 探测大小、5 帧帧率探测），避免低帧率纯视频耗尽预览启动时限；这些参数不修改 RTSP/ONVIF 路径，也不是首次出图时间保证。

实现依据：[SRS 6 外部 SIP](https://ossrs.io/lts/zh-cn/docs/v6/doc/gb28181#external-sip)、[SIP RFC 3261](https://www.rfc-editor.org/rfc/rfc3261)。媒体释放、租约及本机控制限制补丁仅应用于构建副本，不修改 `3rd/`。上游能力不等于本分支设备验收结果。
