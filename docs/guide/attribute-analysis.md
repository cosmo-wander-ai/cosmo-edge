# 目标属性分析

属性分析将同一追踪目标经过多个分类节点的结果整理为一条事件，支持属性明细、组合筛选、统计和 CSV 导出。它复用现有检测、追踪、分类、结果累计和事件上报组件，不需要新增推理模型类型。

## 配置场景和通道

1. 在“场景任务”新建视频分析任务，类型选择“属性分析”。
2. 按顺序连接“视频解码 → 目标检测 → 目标追踪 → 分类 A → 分类 B → 结果累计 → 事件上报”。分类节点使用 `AA_00002`，可以串联更多节点；本版本不支持用多分支汇合代替串联。
3. 在“结果累计”中，将“累计用途”设为“目标属性”，然后添加属性定义。对象类型、分类来源、属性类型（单选、多选或是／否）、置信度阈值和稳定占比优先使用下拉选择。模型标签从所选分类节点读取，内部属性标识和值标识自动生成，不需要手填。显示名称自动填入，也可从候选项选择或自定义；特殊阈值在“自定义阈值与占比”中调整。
4. 单选、多选类型将原始标签映射到属性值标识和显示名称，例如 `wearing_hat → yes → 戴帽`、`no_hat → no → 未戴帽`。只有正向分数的行为标签应选“是／否”，绑定一个模型标签，分别设置肯定、否定值及名称，例如“打电话／未打电话”。缺少模型输出仍不能当作否定结果。
5. 保存场景，绑定视频通道并设置检测区域。任务参数可调整最少有效判断次数、最短观察时间、消失等待时间和采样间隔。属性定义由场景统一管理。

分类模型须事先安装，并与运行平台匹配。本功能没有预置通用人体属性模型；不同模型的标签体系需要分别映射。同一个分类节点可以为多个属性供给标签；复用同一模型的不同节点按节点分别累计。每个场景允许一个属性累计节点。

默认最少有效样本数为 3，最短观察时间 3000 毫秒，目标消失等待时间 1000 毫秒，采样间隔 200 毫秒。观察时长按第一次到最后一次出现计算。未达到观察时长的目标不输出记录；观察时长达标但某些属性证据不足时，输出部分属性待定的记录。

## 一条轨迹对应一条记录

累计使用追踪器的轨迹 UUID，记录编号结合任务运行会话生成，数据库按该编号幂等写入。同一目标命中多个区域，区域编号保存在同一条记录中。目标仍被追踪器输出时不会结束，追踪器停止输出后才开始等待消失超时。

单选属性取本次输出中达到阈值的唯一最高分标签，再按有效样本投票；并列最高分不计数。多选属性分别累计各标签。达到最少有效样本数、标签得票占有效样本比例达到稳定占比后，形成有效属性值。没有映射标签或置信度不足的输出不计为有效样本；多选的分母也是有映射标签的有效样本数。

“是／否”类型用于每次正常推理都会返回正向分数的标签。分数达到阈值（含相等）投肯定票，低于阈值投否定票；两者都计入有效样本数，并按全部有效样本计算稳定占比。缺少绑定标签、分数不是有限的 0 到 1 数值、被过滤的目标和失败推理都不产生否定票。达到最少样本数且一方占比达到要求后，输出该方的属性值；否则为“无法判断”。此类型只适用于完整分数输出，不能用于已丢弃低分项的结果。

缺少输出或证据不足为“无法判断”；从未得到有效样本且发生推理失败为“推理失败”。缺失、失败、无法判断均不隐式变成否定值。属性置信度表示获选标签各次命中置信度的均值，多值时再对这些均值求平均；是／否类型的肯定票使用原分数，否定票使用 `1 - 原分数`，它是聚合分数，不代表经过校准的概率。

失败帧不作为目标离开的证据。任务停止、重启、修改累计参数或区域、视频会话切换，以及长时间输入中断，会丢弃未完成的累计记录。文件视频在最后一帧仍存在的目标不会因文件结束自动输出；它需要后续正常帧证明离开。当前最多同时保留 256 条未结束轨迹，超出容量的新轨迹暂不纳入累计。

“对象”指一次任务运行中的一段轨迹。离开后重新进入、追踪 ID 切换、任务重启、跨通道均可能产生新记录；本功能不做身份识别或跨通道去重。

## 事件中心

进入“事件中心 → 属性分析”，选择一个场景、一个或多个通道和时间范围。通道不选表示该场景的全部通道。表格列从属性定义读取，记录详情展示每个属性的值、状态、有效样本数和置信度。

每条记录保存属性定义快照和版本指纹。修改属性名称、模型来源、标签映射或阈值会产生新版本。查询可切换历史定义版本；不同版本的结果不混合计算占比。多个属性筛选按 AND 组合，多选属性匹配其中一个值。

已有单选行为属性需要在场景编辑中改为“是／否”，配置否定显示名称并保存后才对新记录生效。历史“无法判断”没有保留足够的逐帧分数，不会追溯转换为否定值。新的否定值与肯定值一样支持筛选、统计、详情和 CSV 导出。

统计覆盖全部匹配记录，不受分页影响。有效属性值的占比以该属性有有效结果的对象数为分母；“无法判断”和“推理失败”单独计数。多选属性的占比相加可能超过 100%。CSV 导出使用最后一次查询条件，并保留记录所属版本的名称。

## 数据接口

属性事件使用事件类别 `12`，HTTP/MQTT 推送沿用现有事件通道，属性数据放在 `property.attributes`。其中包含 `recordId`、`trackId`、`schemaId`、`schema`、`firstSeen`、`lastSeen`、`areaIds` 和 `attributes`。属性项包含 `key`、`status`（`valid` / `unknown` / `failed`）、`values`、`confidence`、`samples`。

是／否属性定义使用 `type: "binary"`，`options` 必须恰好包含两项：第一项是肯定值，其 `label` 绑定正向模型标签；第二项是否定值，其 `label` 固定为空字符串，`value` 和 `name` 分别指定否定值标识和显示名称。例如 `[{"label":"calling","value":"yes","name":"打电话"},{"label":"","value":"no","name":"未打电话"}]`。两项的 `value` 必须不同。

事件分页与导出接口接受 `channelIds`、`attributeSchemaId` 和 `attributeFilters`；筛选项包含 `key` 以及 `value` 或 `status`。分页查询设置 `includeAttributeSummary=true` 时，返回 `resData.attributeSummary.schemas` 和 `statistics`。属性查询必须指定一个 `algorithmCodes`、`categorys:["12"]` 和有效时间范围；使用属性筛选时还须指定定义版本。

本功能需要设备端与前端一起更新。单元测试与 x86 构建验证不代表特定属性模型精度或目标设备验收，实际模型效果仍需用目标场景视频评估。
