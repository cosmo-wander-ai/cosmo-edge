# 安全说明

本文面向开源发布和部署前检查。它不是完整安全审计报告。

## 敏感信息

发布前不要提交：

- token、密码、密钥、证书私钥
- 真实设备 SN
- 客户名称、项目名称、内部组织信息
- 内部域名、私有 IP、VPN 地址
- 私有模型下载地址
- 未脱敏日志
- 未脱敏图片或视频

## 模型和资源

模型和资源文件可能涉及许可证、客户数据或内部场景配置。发布前应确认：

- 模型权重是否允许公开。
- 模型模板是否包含内部命名。
- 算法模板是否包含真实场景、客户名称或敏感阈值。
- `prebuild/` 下二进制是否允许分发。
- 加密模型相关能力是否要公开。

## 运行时端口

当前运行时涉及：

- Web / nginx
- 后端 HTTP
- WebSocket
- SRS RTMP / API / HTTP stream
- MQTT

部署到公网前，应至少确认：

- 是否启用了必要认证。
- 默认账号和密码是否已修改。
- 是否需要反向代理 TLS。
- SRS API 是否暴露到公网。
- MQTT broker 配置是否安全。
- HTTP 接口是否限制访问来源。

## 开发模式

x86 Docker 开发路径启用 `COSMO_DEV_MODE`，会跳过设备 SN 校验。该模式适合开发和评估，不应直接作为生产授权策略说明。

## 受限模式

非开发模式存在设备 SN 校验，校验失败时进入受限模式。正式开源前需要明确：

- 受限模式的对外说明。
- 生产授权方式。
- 社区用户如何合法运行。
- 认证设备与开源版本的边界。

## 第三方依赖

发布前应审计：

- C/C++ vendored 依赖
- 前端 npm 依赖
- Docker 镜像依赖
- FFmpeg codec 配置
- OpenH264 / x264 / GPL 相关选项

当前 CMake 中存在 `COSMO_ENABLE_GPL_CODECS` 选项。公开发布时应确保默认发布路径不启用不符合发布策略的 GPL codec。

## 漏洞报告

正式开源前建议添加顶层 `SECURITY.md`，说明：

- 漏洞报告邮箱
- 响应时间预期
- 支持的版本
- 不应公开披露的漏洞细节

在 `SECURITY.md` 发布前，可先通过 README 或 GitHub repository contact 信息提供临时安全联系渠道。
